VERDICT: no such keyword exists.  Detail, in the order it was measured:

1. `$NBO HELP $END` is NOT a keyword in NBO 7.0.9.  The binary answers "Unrecognized $NBO
   keyword: HELP" and then runs the DEFAULT job at rc=0 - so the run looks like a success and
   the help text it was asked for does not exist.  The authority is the manual that ships beside
   the binary (nbo7_man.pdf), read with nbo_man_keywords.py.

2. The manual's complete matrix-keyword list (pp. 47-51) is the set of IN-OUT concatenations
   along ONE fixed sequence, AO -> (PNAO) -> NAO -> NHO -> NBO -> NLMO -> NO -> MO, plus the
   operator matrices F/K/V/DM/DI/S on whole sets.  Every name in it is a transformation between
   two COMPLETE basis sets.  Nothing names a stage inside the AO -> NAO step: there is no
   Schmidt matrix, no NMB/NRB intermediate, no occupancy-weighting matrix, and the cascade sweep
   (`nbo_man_keywords.py cascade`) finds the words only in prose, never as a keyword.  The two
   matrices that bracket the gap, AOPNAO (LFN 32) and AONAO (LFN 33), are the finest grain the
   documented interface has.

3. NBODAF, the one candidate that could have carried an undocumented intermediate, writes
   nothing.  The manual's default is LFN 48 (not 60, which the earlier probe used).  Measured:
   bare `NBODAF` is silently ignored - the .nbo is byte-identical to the base arm and no
   confirmation line is printed at all; `NBODAF=48` and `NBODAF=50` DO print
   "/NBODAF / : NBO direct access file written on lfn48" (resp. 50) and create NO FILE, in the
   working directory or anywhere else.  The positive control in the same mechanism, BOAO=W50,
   produced lif.50 at 16095 bytes, so the arm can write when the keyword writes.  The search for
   a file elsewhere was validated by marker files after date(1) on the login node proved 23 s
   BEHIND the filesystem clock, which had silently voided the first attempt's window (0 hits
   everywhere, including the working directory that definitely had been written): /tmp 0 of 716
   entries, /dev/shm 0 of 147, $HOME 0 of 328, /work/akkleemiss/florian 7 of 23392 and all seven
   are this run's own outputs, with the working-directory control at 7 of 8.

4. Three documented levers turned up that were not on the list, and one of them matters:
   PAOPNAO and NAONBO accept a READ parameter (`PAOPNAO=R`, p50-51), which FEEDS a PAO -> PNAO
   transformation into the program and freezes it.  That is an injection point into exactly the
   stage that cannot be read out: gennbo's steps 4-7 can be probed as a function of a controlled
   input without any intermediate output and without touching the binary.  The other two are
   BOAO (AO bond-order matrix, default LFN 49) and SVEC (eigenvectors of the AO overlap), plus
   the useful `MATKEY=W6`, which routes the F15.9 'W' form to standard output and so sidesteps
   the LFN-49 collision that makes the operator matrices overwrite each other.
